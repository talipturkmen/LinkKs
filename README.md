# LinkKS

> **Archived.** This is a 2018 course/learning project and is no longer maintained. Dependencies are outdated and contain known vulnerabilities; do not deploy as-is.

LinkKS is a C# class library for a URL shortener with user accounts. The public API creates short links for long URLs, with optional password, expiry date, one-shot and notification flags, and provides user sign-up, sign-in and profile update. The repository contains only the business layer and a console test program; it has no web front end and no redirect/lookup code.

## Public API (LinkKS.Business)

- `Link.Shorten(longLink, userId, password, expireDate, oneShot, notification)` returns the short link
- `Link.UpdateExpireDate`, `UpdatePassword`, `UpdateNotification`, `UpdateOneShot`
- `User.SignUp`, `User.SignIn`, `User.Update`

Passwords are stored and compared in plain text.

## Tech stack

- C#, .NET Framework 3.5 (`TargetFrameworkVersion` v3.5)
- LINQ to SQL (`LinkKS.dbml`, data context `LinkKSDataContext`)
- SQL Server (connection string in `LinkKS.Business/app.config` points to a local SQL Server Express instance, database `LINK`, Windows authentication)
- Visual Studio solution format 12.00, VisualStudioVersion 14.0 (Visual Studio 2015)

## Structure

```
LinkKS.sln
LinkKS.Business/   Link and User classes, LINQ to SQL model, settings
LinkKS.Test/       console program with one manual call to Link.Update
```

## How it was run

Best effort, not verified in this cleanup:

1. Open `LinkKS.sln` in Visual Studio 2015 or later and build (NuGet packages are not used).
2. Create a database named `LINK` on a local SQL Server instance that matches `LinkKS.Business/LinkKS.dbml`. No schema script is included.
3. Run `LinkKS.Test`. It calls `Link.Update` with a hard-coded GUID; it is a manual smoke test, not a test suite.

Build output (`bin/`, `obj/`) and Visual Studio user files were removed from the repository; they are regenerated by building.
